# 작업 문서: 순환 코스 후보 생성 API

이슈 "[Feat] 순환 코스 후보 생성 API"의 설계, 결정, 확인 결과를 적는다. API 형식은 [api.md](api.md)에 있다.

## 범위

- 포함: FastAPI 서버 구조, `POST /recommend`, 순환 후보 생성, 점수화, 추천 이유 문장
- 제외: 심박 예측 모델(별도 이슈). `predictedHrPct`는 null로 돌려주고, 점수의 강도 항은 1km당 오르막으로 대신한다

## 처리 흐름

1. 출발 좌표가 서비스 범위 안인지 확인한다. 밖이면 400.
2. 가장 가까운 도로 노드를 찾는다. 300m보다 멀면 400.
3. 방향 16개(22.5° 간격)마다 순환 후보를 하나씩 만든다.
4. 목표 거리에서 30% 넘게 벗어난 후보를 버리고, 점수 순으로 서로 다른 코스 3개를 고른다. 하나도 없으면 404.
5. 코스마다 추천 이유 문장을 붙여 돌려준다.

## 순환 후보를 만드는 방법

출발지를 지나는 원을 그리고, 그 원 위에 경유점 A와 B를 둔다. 출발지·A·B는 원에 내접하는 정삼각형이다. 출발 → A → B → 출발을 `pgr_dijkstraVia`로 이으면 순환 코스가 된다.

- 원의 중심은 출발지에서 방향 θ로 반지름 R만큼 떨어진 곳이다. θ를 0°, 22.5°, …, 337.5°로 돌려 16개를 만든다.
- A는 중심에서 θ−60° 방향, B는 θ+60° 방향으로 R만큼 떨어진 점이다.
- 정삼각형 둘레는 3√3 × R이다. 실제 도로는 직선보다 돌아가므로 우회 비율 1.3을 곱해 `R = 목표 거리 ÷ (3√3 × 1.3)`으로 잡는다. 목표 거리의 약 1/6.75다.
- 결과 거리가 목표의 ±15%를 벗어나면 `R × (목표 ÷ 결과)`로 반지름을 고쳐 한 번 더 시도하고, 목표에 더 가까운 쪽을 남긴다.
- 탐색은 출발지 기준 사방 `목표 거리 × 0.6` 범위의 도로만 쓴다(GiST 인덱스).

설계 문서는 "출발지에서 반경 D/6 떨어진 경유점 2개"라고만 적었다. 출발지에서 경유점까지를 D/6으로 잡으면 코스가 목표의 절반 정도로 짧게 나와서, D/6을 원의 반지름으로 해석했다. 원 둘레(2π × D/6 ≈ D)와도 맞는다.

## 구간 비용

전처리에서 만들어 둔 컬럼에 강도별 k만 곱한다. 설계 문서의 `길이 × (1 + k × max(0, 경사 − 8)²)`와 같은 값이다.

```
정방향 비용 = length_m + k × up_pen_fwd + 0.5 × down_len_fwd
역방향 비용 = length_m + k × up_pen_rev + 0.5 × down_len_rev
계단        = length_m × 100 (양방향)
```

| 강도 | k |
|---|---|
| EASY | 0.5 |
| NORMAL | 0.2 |
| HARD | 0.05 |

## 점수

낮을수록 좋다.

```
점수 = 1.0 × |거리 − 목표| ÷ 목표
     + 0.5 × 왕복 중복률
     + 0.02 × |1km당 오르막 − 강도별 목표|
```

- 왕복 중복률: 같은 구간을 두 번 이상 지나는 거리의 비율
- 1km당 오르막 목표: EASY 0m, NORMAL 15m, HARD 30m. EASY는 평탄할수록, HARD는 1km당 30m에 가까울수록 점수가 좋다. 목표를 넘는 산길(1km당 50m 등)은 HARD에서도 감점된다.
- 오르막 항은 심박 예측 모델을 붙이기 전까지의 대체 항이다. 모델이 생기면 설계 문서대로 `|예상 강도 − 목표 강도 중앙|`으로 바꾼다. 식의 모양을 같게 해 둬서 항만 갈아 끼우면 된다.
- 이미 고른 코스와 구간의 70% 넘게 겹치는 후보는 같은 코스로 보고 건너뛴다. 방향만 다르고 길이 같은 코스 3개가 나오는 것을 막는다.

## 추천 이유 문장

계산된 값만 채우는 템플릿이다.

```
목표 5km 기준 5.1km 순환 코스예요. 누적 오르막 30m, 최대 경사 6.7%이고, '보통' 강도라 가파른 오르막은 되도록 줄였어요.
```

최근 기록이 있으면 평균 페이스(총 시간 ÷ 총 거리)로 예상 소요 시간을 덧붙인다.

```
최근 5회 평균 페이스(6'03"/km)로 달리면 약 31분 걸려요.
```

강도별 문구는 경로 탐색이 실제로 한 일만 말한다. 지형상 오르막을 피할 수 없는 곳에서도 틀린 말이 되지 않게 하기 위해서다.

## 설계 문서에 없어서 정한 것

| 항목 | 값 | 이유 |
|---|---|---|
| 목표 거리 범위 | 1~20km | 범위 밖은 422 |
| 출발지와 도로 사이 최대 거리 | 300m | 도로가 없는 곳(호수, 산)에서 엉뚱한 곳을 출발점으로 잡지 않게 |
| 추천 제외 기준 | 목표 거리 ±30% 초과 | 목표 5km에 2.3km 코스가 나온 사례가 있었다 |
| 비슷한 코스 제외 | 구간 70% 초과 겹침 | 서로 다른 코스 3개를 주기 위해 |
| 우회 비율 초기값 | 1.3 | 대전대·대전역 부근 결과로 맞춘 값 |
| 후보 방향 수 | 16개 (설계 문서는 8개) | 8개로는 강도별로 고를 후보가 부족했다. 응답 시간이 약 2배가 된다 (5km 0.43초, 20km 0.89초) |
| 1km당 오르막 목표 | EASY 0 / NORMAL 15 / HARD 30 (m) | 대전대 부근 후보들이 12~31m 범위에 분포 |
| 오르막 가중치 | 0.02 | 0.01·0.015·0.02를 비교해 강도 차이가 가장 뚜렷한 값 |

전부 `app/config.py`에 있다. 실제로 뛰어 보며 조정한다.

## 알려진 한계

- **강도 차이는 지형에 달려 있다.** 경로 탐색에서 k는 가파른 오르막을 피하는 정도만 바꾸고, HARD가 오르막을 찾아가지는 않는다. 차이는 만들어진 후보 16개 중에서 점수로 고를 때 생긴다. 대전역처럼 평탄한 곳은 후보가 전부 평탄해서 NORMAL과 HARD가 같은 코스를 추천한다.
- **강도 기준이 오르막뿐이다.** 같은 코스라도 사람마다 힘든 정도가 다른데 지금은 반영하지 못한다. 심박 예측 모델의 몫이다.
- **산 근처에서는 EASY도 가파르다.** 식장산 자락에서 5km EASY를 요청하면 가장 평탄한 코스도 누적 오르막이 125m다. 경유점이 산길에 잡히면 피할 길이 없다.
- **최대 경사는 실제보다 크게 나올 수 있다.** 30m 구간 기준이고 고도 데이터가 지표면 모델이라, 건물이나 절개지 옆에서 튀는 값이 섞인다. 대전대 부근 코스에서 14~29%가 자주 나온다.
- 경사값을 실측과 대조하지 못했다.
